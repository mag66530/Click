# Click – пакетная публикация в Яндекс.Бизнес

Приложение публикует один пост сразу во много карточек Яндекс.Бизнеса (по городам и
странам), а потом показывает честный отчёт – что реально опубликовалось, что нет и почему.
Кроме Яндекса Click работает с **2ГИС**: актуализирует данные карточек и готовит ответы
на отзывы (см. «Вторая площадка – 2ГИС»).

Пять проектов в одном приложении, у каждого свой аккаунт Яндекса, свои города, свои
окончания постов и свой промпт для ответов на отзывы:

| | | |
|---|---|---|
| 🏗 **СМУ** | Стальметурал | 117 городов |
| 🔩 **ИМП** | Инметпром | 144 города |
| ⚡ **МПЭ** | МетПромЭнерго | 142 города |
| 🛠 **МПИ** | МетПромИнтекс | города из КП |
| ✈ **АПС** | Авиапромсталь | 62 города |

## Запуск

**Windows** – двойной клик по `START.bat`.
**macOS / Linux** – `./START.command`.

Первый запуск сам поставит Python-зависимости и браузер (1-3 минуты), дальше стартует
за пару секунд. Откроется `http://localhost:8501`. Пароли проектов – те же, что были
в `projects.js`.

Вручную, если нужно:

```bash
pip install -r requirements.txt
python -m playwright install chromium
streamlit run streamlit_app.py
```

На Linux-сервере могут понадобиться системные библиотеки для браузера:

```bash
python -m playwright install-deps chromium
```

`packages.txt` – тот же список для Streamlit Cloud.

### Веб-сервисы на своём компьютере

Всё, что ходит в интернет – черновики отзывов (Gemini), таблица КП (Google),
хранение данных между перезапусками (GitHub), – нужны ключи. В облаке они
лежат в секретах Streamlit; локально секретов нет, и раньше приходилось
руками создавать `.streamlit/secrets.toml`.

Теперь проще: **«⚙️ Настройки» → «Ключи к веб-сервисам»**. Вписали, нажали
«Сохранить ключи» – работает. Порядок поиска у всех ключей одинаковый:

    переменная окружения → секреты Streamlit → настройки приложения

Облако как работало, так и работает: там первые два источника заполнены, и
до настроек дело не доходит. Если ключ задан переменной или секретом, поле
в настройках не показывается – вместо него написано, откуда ключ берётся.

Ключи лежат в `users-data/secrets.json` – это **вне папки Click** (там же,
где сессия Яндекса и города). Обновление программы их не тронет, а в
репозиторий они попасть не могут: в папке проекта их просто нет. Шифрования
нет – файл того же уровня доступа, что и сохранённая сессия.

Для Яндекса и 2ГИС ключей не нужно вовсе: логин и пароль вписываются там же,
в «Настройках», а вход происходит через браузер.

## Как пользоваться

1. **Настройки** → впишите email Яндекс.Бизнеса → **Вход в Яндекс**.
   Браузер работает скрыто, вместо окна вы видите скриншот и вводите логин, пароль и код
   обычными полями. Сессия сохраняется – дальше 2FA не нужна.
2. **Публикация** → тип поста → текст → картинки → страны и города → **в очередь**.
   Контакты и хэштеги подставляются автоматически по стране и проекту, итоговый текст
   виден в превью до отправки.
3. **Очередь → задачи**, потом **Запуск** → «Опубликовать». Прогон идёт в фоне, лог
   обновляется сам, есть кнопка «Остановить».
4. **Отчёт** – по каждому городу статус и причина, фильтры, выгрузка CSV.

## Сверка КП с Яндексом

Раздел **«Сверка»** отвечает на вопрос «что у нас на самом деле заведено в Яндексе».
Click читает список организаций аккаунта, раскладывает их по городам КП и сравнивает
сайт, телефоны и почту с таблицей.

| | |
|---|---|
| **✅ Найдено** | городу соответствует ровно одна карточка |
| **❗ Несколько** | карточек две и больше – дубли, посты уходят в одну, вторая живёт своей жизнью |
| **❌ Нет в Яндексе** | город в КП есть, карточки нет |
| **⚠ Расхождения** | карточка есть, но сайт, телефон или почта не совпали с КП |
| **➕ Лишние** | карточка в Яндексе есть, а города в КП нет |

Город и карточка связываются по адресу («городской округ Шахты, Шахты» – это Шахты)
и по городскому сайту (`shahty.aviastal.ru`); если в КП уже стоит прямая ссылка на
карточку, она главнее всего. Организации читаются из раздела «Организации» – там
Яндекс сразу отдаёт адрес, сайт, телефоны и почту, поэтому открывать каждую карточку
не нужно; галочка «Открывать карточку каждой организации» на всякий случай осталась.

Отчёт – книга из девяти листов, по листу на вопрос (оформление то же, что в
отчёте site-checker «Проверка КП»):

| Лист | Что там |
|---|---|
| **Дашборд** | сводка цифрами и по какому полю сколько расхождений |
| **Как читать** | что означают ✓ ✗ ⚠ – |
| **Нет в КП** | организации Яндекса без города в КП, **со ссылкой на каждую карточку** |
| **Нет ссылки в КП** | город в КП есть и карточка нашлась, но ссылки на неё в КП не записано – скопируйте из отчёта |
| **Дубли** | города с несколькими карточками, по строке на карточку. Города, которых нет в КП, тоже здесь – с пометкой в колонке «Страна» |
| **Нет в Яндексе** | города КП, для которых карточки не нашлось |
| **Расхождения** | каждое расхождение строкой: слева КП, справа Яндекс |
| **Сверка** | сетка ✓/✗ по всем городам, подробности в примечании к ячейке |
| **КП с данными** | ваша таблица без единого изменения плюс колонки из Яндекса |

## Ответы на отзывы

В «Актуализации» есть галочка **«Заодно проверить отзывы и подготовить ответы»**.
С ней прогон, кроме кнопки «Данные актуальны», заходит в раздел «Отзывы» каждой
карточки, находит отзывы без ответа компании и пишет черновики ответов через
Google Gemini – по промпту, своему у каждого проекта.

**В Яндекс ничего не уходит само.** Собранные пары «отзыв → черновик» ждут вас
наверху вкладки «Актуализация»: текст можно поправить прямо там, попросить другой
вариант кнопкой «Переписать» или пропустить. Отправляется только то, что вы
подтвердили, и только когда не идёт ни один прогон: отправка водит браузер сама,
а лишний браузер приложение по памяти не тянет (см. «Параллельные прогоны»).

Правила отбора:

| | |
|---|---|
| **5 звёзд** | пишем черновик |
| **меньше 5 звёзд** | черновик не пишем – отзыв попадает в список со ссылкой на карточку, отвечаете сами |
| **без текста** (одни звёзды) | пропускаем молча |
| **уже с ответом** | не трогаем, в том числе если ответили мы же раньше |
| **пропущенный** | «Убрать из списка» убирает отзыв с глаз, но в кабинете он остался без ответа – следующий прогон принесёт его снова, со свежим черновиком |

Не больше 20 черновиков на город – страховка от карточки с аномальным числом
отзывов. Возраст отзыва не важен: на старые неотвеченные тоже отвечаем.
Со страницы берутся первые 20 отзывов – столько Яндекс отдаёт за раз.

Перед самой отправкой Click ещё раз читает отзыв: если на него успели ответить
без нас, публикация отменяется. Двух ответов на один отзыв не будет.

**Если сессия Яндекса слетела**, прогон останавливается на первом же городе и
говорит об этом прямо: «зайдите в «Настройки» и войдите в Яндекс заново».
Раньше актуализация этого не замечала – вместо кабинета открывалась страница
входа, кнопки «Данные актуальны» на ней нет, и каждый город получал
«актуализация не требуется». Полчаса работы и отчёт, полный неправды.

**У МПИ свой вид ответа**, утверждённый образцами: первая строка «Спасибо за
отзыв и рекомендацию!» – но только если клиент нас и правда кому-то рекомендует
(«рекомендую», «советую всем»). Если про рекомендацию в отзыве ни слова, первая
строка просто «Спасибо за отзыв!»: благодарить за то, чего не было, нельзя.
Следом абзац, который начинается сразу с сути
(«Приятно слышать, что …») и всегда заканчивается фразой про ассортимент, и
подпись – между частями пустая строка. Второй раз благодарить за отзыв нельзя:
«Спасибо за отзыв» и тут же «Благодарим вас за отзыв» – это одно и то же
дважды. Слово «очень» не используется вовсе: не «Нам очень приятно», а
«Приятно слышать»; не «Очень рады», а «Мы рады». Промпт этого
требует, а код ставит на место, если модель всё же уйдёт: у остальных четырёх
брендов ассортиментная фраза стоит отдельным абзацем, у МПИ – последним
предложением абзаца.

**Отвечает компания, а не приятель.** Слова из отзыва в ответ не переносятся
дословно: «классный выбор» – это «широкий выбор», «ценники» – «цены», «доставка
была быстрая» – «оперативная доставка». Суть отзыва при этом сохраняется: о чём
написал клиент, о том и отвечаем. Ходовые сочетания код заменяет сам, а что не
смог – показывает предупреждением под черновиком («разговорные слова в ответе от
лица компании: «классный»»), и дальше ваше решение: «Переписать» или поправить
руками.

**Ключ Gemini.** Берётся бесплатно в Google AI Studio кнопкой **«Get API key»**.
Вписать его можно двумя способами: в самом приложении («⚙️ Настройки» → «Ключи
к веб-сервисам») или секретом приложения (Settings → Secrets):

```toml
gemini_api_key = "AIza…"
```

**Ключ должен начинаться с `AIza`** и быть длиной около 39 знаков. Это важнее,
чем кажется: Google смотрит на начало значения и по нему решает, что ему
прислали. Значение вида `AQ.Ab8…` он ключом не считает вовсе – это учётные
данные OAuth, и ответ на них один: `401 Expected OAuth 2 access token`, куда
его ни положи. На этом уже потеряли вечер: ключ в поле стоял, а черновики не
писались.

**«🔎 Проверить ключи»** («⚙️ Настройки» → «Ключи к веб-сервисам» → Gemini) –
спрашивает у Google про каждый ключ отдельно и показывает его ответ: работает,
недействителен, не включён Generative Language API, ограничен по адресу. Это
первое, что стоит нажать, если черновиков нет.

**Ключей лучше несколько.** На бесплатном тарифе Gemini считает запросы в минуту
**на каждый ключ отдельно**, и генерация двух десятков черновиков упирается именно
в этот лимит. Заведите в AI Studio ещё один-два ключа и добавьте:

```toml
gemini_api_key_2 = "AIza…"
gemini_api_key_3 = "AIza…"
```

Click распределяет запросы между ними: ключ, который отказал по лимиту, на минуту
откладывается, а работа продолжается остальными. Два ключа – вдвое быстрее, три –
втрое. Можно записать и одной строкой: `gemini_api_keys = "ключ1,ключ2,ключ3"`.

Локально можно вместо секрета задать переменную `GEMINI_API_KEY`. Без ключа
отзывы всё равно соберутся – просто без черновиков, с полем для ручного ввода.

**Промпт** правится в «Настройках» → «Ответы на отзывы», отдельно для каждого
проекта. Заводские промпты – текст заказчика, перенесённый дословно. Маркеры
`[вставить отзыв]` и `[имя]` заменяются на текст отзыва и имя автора, убирать их
нельзя. Кнопка «Вернуть заводской» откатывает правки.

Имя подставляется, только если оно похоже на имя: «Надежда Х.» → «Надежда», а
никнеймы, номера и грубость заменяются на «Клиент». У МПИ обращения по имени нет
вовсе – так написан его промпт.

### Если что-то не так

* **«Отзывы не прочитаны»** – Click не нашёл на странице `window.__PRELOAD_DATA`.
  Скорее всего Яндекс поменял отдачу страницы; причина пишется в лог прогона.
* **«Gemini придерживает запросы по лимиту»** – бесплатный тариф. Отзыв останется
  в списке с полем для ручного ввода, остальные города обработаются дальше.
  Лечится вторым и третьим ключом (см. выше).
* **«Не нашли поле „Ответ компании“»** – вёрстка страницы изменилась. Ответить
  можно вручную по ссылке из списка.
* **Кнопка «Отправить» неактивна** – идёт прогон. Дождитесь его конца.

## Вторая площадка – 2ГИС

В разделе **«🔄 Актуализация»** наверху переключатель: **Яндекс.Бизнес | 2ГИС**.
Обе половины устроены одинаково – тот же выбор городов, тот же прогон, та же очередь
ответов на подтверждении. Отличается то, что за ними стоит.

| | Яндекс.Бизнес | 2ГИС |
|---|---|---|
| Что нажимаем | «Данные актуальны» в разделе «Данные» | «Данные верны» в разделе «Данные о компании» |
| Подтверждение | всплывашка «Данные актуализированы» | плашка «Спасибо за подтверждение данных» |
| Отзывы | раздел «Отзывы» карточки | `…/reviews?withoutAnswer=true` – сразу только неотвеченные |
| Ответ | поле «Ответ компании» → кружок со стрелкой | «Ответить» → текст → «Опубликовать» |
| Вход | почта + подтверждение с почты | почта + пароль в «Настройках» |

**Города берутся из той же КП.** В таблице у каждой площадки свой блок
«Аккаунт – Карта – Статус»; для 2ГИС нужен «Аккаунт» – ссылка вида
`account.2gis.com/orgs/<номер>/`. Город попадает в список 2ГИС, если такая ссылка есть,
а статус не «Удалена», «Добавить» или «Не активна». Статусы у площадок независимы:
карточку могли удалить в Яндексе и оставить живой в 2ГИС – город останется в списке 2ГИС.

**Обновить список – кнопкой «⟳ Обновить города из КП»**, она стоит прямо над списком
городов: и на «Актуализации» (для той площадки, что выбрана наверху), и на вкладке
«Города». Рядом написано, сколько городов в списке ЭТОЙ площадки и когда список
перечитывался в прошлый раз. Поправили статус в таблице – нажали кнопку, список
перечитался сразу; сам по себе он тоже обновляется, но раз в несколько часов.

**Города нет в списке 2ГИС – Click скажет, почему.** После загрузки он перечисляет
непопавшие города по именам с причиной: «Шымкент – статус «Удалена»», «Актобе – в
колонке 2ГИС не ссылка на кабинет», «Тараз – в ссылке нет номера организации».
Причина всегда в строке КП: без ссылки на кабинет и с «мёртвым» статусом работать
не с чем.

**Отзывы с чужих площадок.** Кабинет 2ГИС показывает вместе со своими отзывы с Flamp,
Otello, Booking, НетМонета, Т-Банка и СберЧаевых. Ответить на них оттуда нельзя – вместо
кнопки там ссылка «Посмотреть на …». Click такие отзывы **не отдаёт Gemini**, а кладёт в
список с пометкой «ответить можно только там» и ссылкой, куда идти. В итогах прогона они
считаются отдельной строкой.

Правила отбора те же, что у Яндекса: 5 звёзд – черновик, ниже – человеку, без текста –
молча мимо. Промпт **один на обе площадки** – он про то, как отвечать, а не про то, где.

**Прогон 2ГИС не запускается рядом с яндексовым** (и наоборот): это второй тяжёлый
браузер, а бесплатному облаку хватает и одного. Файлы у прогонов разные – свои задачи,
свой отчёт, свой лог и своя кнопка «Остановить», так что ничего не перемешивается.

**Вход.** «Настройки» → «Вход в 2ГИС»: почта и пароль кабинета, одна учётка на проект –
в ней все города. Пароль остаётся только в этом контейнере, наружу уезжает лишь сессия –
поэтому после перезапуска облака входить заново обычно не нужно. Если 2ГИС попросит код
подтверждения, поле для него появится там же, рядом со снимком экрана.

**Как Click находит «Данные верны».** Не по кнопке – кнопки там нет. В кабинете это
обычная надпись в плашке: ни роли, ни рамки, ни фокуса, и текст её живёт то отдельным
словом, то куском строки («…они не изменились? Данные верны»). Поэтому Click читает
страницу целиком – включая теневые корни и врезанные кадры, куда обычное чтение текста
не заглядывает, – находит МЕСТО, где нарисована фраза, и кликает мышью ровно туда, как
это сделал бы палец. Ждёт он при этом не «сколько-нибудь секунд», а пока страница
перестанет меняться – **и не меньше девяти секунд**: плашку кабинет забирает отдельным
запросом и рисует позже остального, а сама страница успокаивается за пару секунд.
Именно на этом Click дважды обжёгся: тишина на странице ещё не значит, что кабинет
всё отдал.

**Отзывы ждут так же.** «Отзывов пока нет» пишется, только если раздел ДЕЙСТВИТЕЛЬНО
дорисован – видны фильтр «Без ответа», карточки или прямая надпись кабинета, что
отзывов нет, – и с открытия страницы прошло не меньше девяти секунд. Слово «Отзывы»
из меню кабинета за готовность не считается: на этом Click однажды объявил Ош
городом без отзывов, хотя отзыв там висел. Не дорисовалась вовсе – страница
перезагружается ещё раз, а если и это не помогло, город получает честное «список не
пришёл, отзывы могли остаться незамеченными», а не спокойный ноль в отчёте.

**Успех не предполагается.** Город считается подтверждённым, только если кабинет ответил:
всплыла плашка «Спасибо за подтверждение данных» или со страницы убрался сам вопрос.
Нажали, а ответа нет – так и написано в отчёте, и туда же кладётся снимок экрана.
«Плашки нет – подтверждать нечего» пишется лишь тогда, когда мы точно на нужной странице,
она дорисована и вопроса на ней действительно не видно.

### Фото отгрузки – сразу на обе площадки

У поста типа **«Отгрузка»** под полем «Фото в раздел „Товары"» стоит галочка
**«Опубликовать эти фото ещё и в 2ГИС»**. Файлы берутся те же самые и качаются один раз
на обе площадки. Галочка помнит прошлый выбор проекта: первый раз выключена, дальше стоит
так, как оставили.

Порядок на каждом городе: пост в Яндекс → фото в «Товары» Яндекса → те же фото в
«Фото и видео» 2ГИС. Третий шаг полностью отдельный: что бы там ни случилось, **статус
публикации поста не меняется** – пост уже стоит в карточке, и объявлять его неудачным
из-за фотографии было бы неправдой.

Что важно знать:

* **Только после успешной публикации.** Пост не встал – фото не льются никуда.
* **Успех только доказанный – страницей ПОСЛЕ перезагрузки, а не тем, что показал
  браузер сразу.** Кабинет 2ГИС рисует плитку в альбоме «оптимистично», ещё до того,
  как сервер принял файл; если сервер его отклонил, плитка тихо пропадает. Click
  ждёт, потом перезагружает страницу и верит только свежему ответу сервера – иначе
  отчёт может написать «добавлено», а в кабинете останется пусто. «Файлы переданы»
  успехом не считается – в отчёте будет «проверьте вручную».
* **Перепроверок несколько: через 2, 4 и 8 секунд.** 2ГИС принимает файл не мгновенно,
  и одна проверка сразу после перезагрузки регулярно врала «фото не появилось», хотя
  снимок уже лежал в кабинете. Плитки считаются только на дорисованном альбоме, а перед
  счётом страница прокручивается до низа – иначе новый снимок теряется среди
  существующих и в поле зрения не попадает вовсе.
* **Город без карточки 2ГИС** получает спокойное «Нет карточки в 2ГИС» и идёт дальше.
* **gif 2ГИС не принимает** – такие файлы отсеиваются заранее, с именем файла в логе.
  Иначе 2ГИС отказал бы молча.
* **Повтор не заливает второй раз.** Click помнит «эти снимки → эта карточка» и считает
  их по содержимому файлов, а не по именам: одна и та же фотография, скачанная дважды,
  ложится во временную папку под разными именами.
* В отчёте у города – пометка **📸 2ГИС: 3/3**, в выгрузке CSV – своя колонка.

Сессия 2ГИС для этого нужна та же, что и для актуализации – из «Настроек». Её нет –
одна строка в логе, фото пропускаются, публикация в Яндекс идёт как обычно.

Вкладка 2ГИС живёт в том же браузере отдельной сессией и **переживает перезапуск
браузера**: посреди длинного прогона сторож памяти браузер перезапускает, и вкладка
уходит вместе с ним. Раньше прогон помнил её сам – и после перезапуска все оставшиеся
города получали «Кабинет 2ГИС не открылся: Event loop is closed». Теперь вкладка
спрашивается у браузера каждый раз и заводится заново.

**Если карточка 2ГИС для города не заведена в списке**, фото туда не уйдут: город
получит «Нет карточки в 2ГИС». Список 2ГИС отдельный от Яндекса и обычно короче –
посмотреть и дополнить его можно в разделе 2ГИС.

### Добавить фото в 2ГИС (без поста)

У типа поста **«Отгрузка»**, под блоком «Товары», стоит отдельное поле
**«Добавить фото в 2ГИС»**. Оно заведено, чтобы залить фото в 2ГИС, не публикуя ради
этого десятки постов. У остальных типов поста этого блока нет – он, как и «Товары»,
имеет смысл только у отгрузки.

Как работает: кладёте туда ссылки или файлы, выбираете страны и города как обычно, и
кнопка сама меняется на **«📸 Фото в 2ГИС»**. Дальше всё то же: «Сохранить очередь в
задачи» → «Запуск». На «Запуске» видно, что это не публикация: шаг называется «Фото в
2ГИС», кнопка – «Залить фото в 2ГИС».

**Очередь у них своя, отдельная от постов.** Это не про порядок в папках. Прогон
прежней сборки про такие задания не знает: он видит задачу без текста поста и
публикует пустой пост – так и вышло у заказчика, пять пустых постов в живых карточках.
В чужую папку он не заглянет, потому что в его коде её нет: очередь для него просто
пуста, и он ничего не делает. Если в очереди окажутся сразу и посты, и фото в 2ГИС,
запуск блокируется до тех пор, пока одно из двух не убрано – каждую очередь можно
очистить своей кнопкой.

Что при этом НЕ происходит: пост не публикуется, фото в «Товары» Яндекса не льются,
аккаунт Яндекса не проверяется – для такого прогона нужна сессия **2ГИС**, а не Яндекса.
Текст поста и это поле одновременно не работают: это разные режимы, и Click скажет
об этом, а добавить в очередь не даст, пока одно из двух не убрано.

## Что было в прогоне

У каждого отчёта сверху стоит **заголовок прогона** – по цифрам отчёты не различить,
а делают они разное:

| Заголовок | Что происходило |
|---|---|
| **Публикация · отгрузка + фото в «Товары» + фото в 2ГИС** | пост, фото в «Товары» Яндекса и те же фото в 2ГИС |
| **Публикация · информационный пост** | только пост |
| **Только фото в 2ГИС, без постов** | временный режим: снимки в «Фото и видео», постов нет |
| **Актуализация Яндекс** | кнопка «Данные актуальны» |
| **Актуализация 2ГИС + проверка отзывов** | то же плюс сбор отзывов и черновики ответов |

Тот же заголовок стоит первой строкой в логе прогона.

**Пустой пост не публикуется никогда.** Задача без текста – это либо «только фото в
2ГИС», либо ошибка; в обоих случаях кнопка «Создать» не нажимается, а город получает
в отчёте «Пустой текст поста – публиковать нечего». Проверка стоит дважды: у прогона и
у самой кнопки. Однажды пустые посты ушли в три города по-настоящему – после обновления
экран уже умел задания «только фото в 2ГИС», а прогон в памяти остался от прежней
сборки и принял их за обычные.

**Приложение не работает вразнобой.** Облако обновляет файлы под работающим
приложением, но с диска Streamlit перечитывает только главный экран – остальное
берёт из памяти. До перезапуска приложение живёт наполовину новым: экран свежий,
прогон прежний. Это давало и ошибки на экране («AttributeError»), и пустые посты в
живых карточках – новый экран складывал задания «только фото в 2ГИС», а старый прогон
принимал их за обычные.

Теперь метка сборки сверяется **с диском**, а не с памятью (в памяти она устаревает
вместе со всем остальным, и тогда «всё сходится» при разном коде). Разошлась – Click
перечитывает отставшие части сам и продолжает работу. Пока это не удалось – страница
ничего не рисует и **ничего не запускает**: смешанный код опаснее неудобства. Если
идёт прогон, обновление откладывается до его конца – прерывать работу нельзя.

## Статусы в отчёте

| | значение |
|---|---|
| ✅ **Успешно** | пост найден в ленте карточки после публикации |
| 🟡 **Без картинки** | пост в ленте есть, картинки в нём нет |
| ⚠️ **Проверьте** | ленту прочитать не удалось, подтверждения нет. **Повторно не публикуется** – откройте карточку и посмотрите глазами |
| ❌ **Ошибка** | поста в ленте нет либо до клика «Создать» не дошли – публиковать заново безопасно |
| ⏭ **Пропущено** | этот же текст уже уходил в эту карточку недавно (защита от дублей) |

Статус ставится **только по ленте карточки**, а не по ответам Яндекса по сети.
12.08.2026 шестьдесят городов отчитались «опубликовано (API подтвердил)», хотя в
Самаре поста не было вовсе, а в Тюмени он вышел без картинки: за подтверждение
публикации принимался ответ загрузчика картинки – хост яндексовый, в адресе есть
`sprav`. Теперь после клика «Создать» страница перечитывается и в ленте ищется
текст поста; HTTP-ответ идёт только в текст причины, решения он не принимает.

## Защита от дублей

Три независимых уровня, любой из них останавливает повтор:

1. **Лок прогона** – пока идёт публикация, вторая публикация не стартует. Ни двойным
   кликом, ни из другой вкладки, ни обновлением страницы, ни из другой копии Click.
   Лок у каждого вида прогона свой (см. «Параллельные прогоны» ниже).
2. **Реестр отправленных** – на каждую отправку пишется отметка «этот текст → эта
   карточка». Тот же текст в тот же город в течение 12 часов (настраивается в
   «Настройках») просто пропускается. Это же позволяет продолжить прогон, оборвавшийся
   на середине, ничего не переопубликовав.
3. **Запрет повтора после клика** – если кнопка «Создать» уже была нажата, автоматическая
   вторая попытка не делается никогда. Такой город получает статус ⚠️ «Проверьте».

Сбросить реестр (например, если нужно осознанно опубликовать тот же текст ещё раз) –
«Настройки» → «Очистить реестр публикаций».

## Параллельные прогоны

Прогонов три вида: **публикация**, **актуализация** и **чтение организаций** (кнопка
на «Сверке»). У каждого свой лок, своё состояние, свой живой лог и своя кнопка
«Остановить» – вкладка показывает свой прогон и не видит соседний.

| | |
|---|---|
| Чтение организаций ∥ актуализация | **можно** |
| Чтение организаций ∥ публикация | **можно** |
| Публикация ∥ публикация | нельзя – это дубли постов |
| Актуализация ∥ актуализация | нельзя – два клика по одному городу |
| Публикация ∥ актуализация | нельзя – два тяжёлых браузера разом |
| Актуализация 2ГИС ∥ любая яндексова | нельзя – по той же причине |

Чтение организаций уживается с чем угодно, потому что ничего в Яндексе не меняет:
оно только читает раздел «Организации».

Последние две строки – про **память**, а не про данные. Каждый прогон поднимает свой
Firefox, и на бесплатном тарифе Streamlit Cloud двух тяжёлых страниц Яндекса уже
хватало, чтобы приложение выбило по лимиту. По той же причине **отправка ответов на
отзывы** ждёт окончания любого прогона: она водит браузер сама, из вкладки.

Разрешить публикацию рядом с актуализацией – одна строка в `CONFLICTS` (`runner.py`),
но делать это стоит, только если приложение переедет на платный тариф. Потолок
`MAX_PARALLEL_RUNS = 2` держит число живых браузеров, даже если видов прогонов
станет больше.

## Настройки прогона

«Настройки» → «Параметры прогона»:

* **Скрытый браузер (headless)** – выключите, если хотите видеть окно браузера.
  Работает только при локальном запуске.
* **Пауза между городами** – 3 секунды по умолчанию. Меньше – рискуете поймать антифлуд.
* **Строгая проверка аккаунта** – останавливать прогон, если в Яндексе залогинен не тот
  аккаунт, которого ждёт проект. Не выключайте: это защита от публикации постов одного
  бренда в карточки другого.
* **Не повторять тот же пост, часов** – окно защиты от дублей.
* **Повторять неопределённые публикации** – выключено, и лучше так и оставить: повтор
  после неподтверждённого клика – главная причина двойных постов.

Браузер по умолчанию Chromium (под него писались селекторы). Если не хватает памяти –
`CLICK_BROWSER=firefox streamlit run streamlit_app.py`.

## Про Streamlit Cloud

Приложение работает и в облаке, но помните две особенности площадки:

* **Файловая система временная.** При перезапуске контейнер собирается заново, и всё
  содержимое папки данных пропадает. Поэтому **города берутся из Google-таблицы КП** –
  она живёт снаружи, и после перезапуска список подтягивается обратно
  («Города» → «Источник городов»). Что всё-таки теряется: сохранённая сессия Яндекса
  (нужно войти заново) и старые отчёты.

  Список городов **обновляется сам**: если с последней загрузки прошло больше шести
  часов, Click перечитывает таблицу при открытии проекта и говорит об этом строкой
  наверху. Кнопка «Загрузить города из таблицы» осталась – для «прямо сейчас».
  Раньше загрузка была только кнопкой, и после перезапуска облака список молча
  откатывался к зашитому в код – города приходилось грузить заново каждый день.

  Для этого в секреты приложения (Settings → Secrets) нужно положить:

  ```toml
  kp_sheet_url_SMU = "https://docs.google.com/spreadsheets/d/…/edit"
  kp_sheet_url_IMP = "…"
  kp_sheet_url_MPE = "…"
  gcp_service_account_b64 = "<весь JSON-ключ сервисного аккаунта в base64>"
  ```

  Таблица должна быть расшарена на сервисный аккаунт как Читатель, в проекте Google
  включён Sheets API. Ссылку можно задать и прямо в приложении – тогда она сохранится
  в настройках проекта.
* **Браузер.** В облаке Click работает через **Firefox**, локально – через **Chromium**.
  Это не прихоть: в облаке Chromium не запускается (нет системной библиотеки
  `libgbm.so.1`, и на бесплатном тарифе ему не хватает памяти на тяжёлых страницах
  Яндекса), а доставить библиотеки туда нельзя – root'а нет. Firefox требует меньше
  и того, и другого. Локально наоборот берётся Chromium: под Chrome писались и
  проверялись все селекторы Яндекс.Бизнеса, там точнее.
  Выбор автоматический, с запасным вариантом в обе стороны. Закрепить жёстко –
  переменная `CLICK_BROWSER=chromium` или `firefox`.

  **`packages.txt` менять осторожно.** Список ставится одной командой `apt-get install`:
  любое имя, которое не резолвится, обрывает установку целиком, и приложение не
  поднимается вообще – «Error installing requirements». Два класса имён запрещены:

  * ставшие **виртуальными** после перехода Ubuntu на 64-битный `time_t` – например
    `libasound2`: на Ubuntu 24.04 его предоставляют сразу два пакета, apt отказывается
    выбирать и падает. Именно на этом приложение и слегло, когда Streamlit Cloud
    пересобрал контейнер на новом образе;
  * сами **`*t64`-имена** (`libasound2t64` и подобные) – их нет на старых образах.

  Проверить перед коммитом: `python tests_click.py` (тест `packages.txt`).

Вход в Яндекс в облаке возможен только по скриншотам – окна браузера там физически нет.
Локально можно открыть настоящее окно (выключите «Скрытый браузер» в «Настройках»).

## Где лежат данные

Личные данные лежат **вне папки проекта**, чтобы обновление Click (скачали новый zip –
новая папка) их не затрагивало:

| | |
|---|---|
| Windows | `%LOCALAPPDATA%\\Click\\users-data` |
| macOS | `~/Library/Application Support/Click/users-data` |
| Linux | `~/.local/share/click/users-data` |

Точный путь всегда виден в «Настройках» → «Обслуживание». Переопределяется переменной
`CLICK_DATA_DIR`. Если папка `users-data/` уже есть внутри проекта (старая установка) –
работаем с ней, ничего не переезжает.

Внутри, по проектам:

```
projects-config.json   email/пароль ЯБ и 2ГИС, страны и города, настройки
session/               сохранённые сессии Яндекса и 2ГИС
tasks/                 очередь на публикацию (done/ – обработанные)
tasks-actualize/       очередь на актуализацию
tasks-actualize-gis/   то же для 2ГИС
reports/               отчёты публикации
reports-actualize/     отчёты актуализации
reports-actualize-gis/ отчёты актуализации 2ГИС
logs/                  логи по дням
uploads/               загруженные картинки
.published.jsonl       реестр отправленных постов (защита от дублей)
```
